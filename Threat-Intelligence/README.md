# CyberShield AI Threat Intelligence v2

This is an operational threat-intelligence backend, not a dashboard that merely prints feed records.

## What it actually does

- Pulls and refreshes the CISA Known Exploited Vulnerabilities catalog in the background.
- Queries NVD for a requested CVE and extracts CVSS/severity/references.
- Detects indicator type automatically: CVE, IP, domain, URL, MD5, SHA1, SHA256.
- Queries ThreatFox when `THREATFOX_AUTH_KEY` is configured.
- Resolves domains and records current DNS results.
- Performs URL feature extraction and can use a trained Random Forest model when a real labeled dataset is supplied.
- Produces a transparent 0-100 risk score with evidence and reasons.
- Stores every check in SQLite so your UI can show history instead of fake static cards.
- Continues using last-known-good CISA data if an upstream refresh fails.

## Important truth about the ML model

There is no honest thing called a "perfect" cybersecurity model. Training on invented or copied labels and then claiming 99% accuracy would be nonsense. The included model trainer requires real labeled URLs and reports a held-out test score. The deterministic intelligence engine remains the authority when external reputation evidence is available.

## Run

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
copy .env.example .env
python app.py
```

API: `http://127.0.0.1:5005`

### Check an indicator

```powershell
curl -X POST http://127.0.0.1:5005/api/indicator/check `
  -H "Content-Type: application/json" `
  -d '{"indicator":"CVE-2024-3400"}'
```

### History

`GET /api/history`

### Health

`GET /api/health`

### Feed status

`GET /api/feeds`

## ThreatFox

ThreatFox requires an Auth-Key for API queries. Put it in `.env` as `THREATFOX_AUTH_KEY`. See the official API documentation: https://threatfox.abuse.ch/api/

## Training the URL model

Create a CSV with:

```csv
url,label
https://example.com,0
https://known-malicious.example/payload,1
```

Use a genuinely labeled dataset, not labels generated by the same rules you are trying to validate.

```powershell
python train_model.py data/url_labels.csv
```

The trainer uses a stratified held-out test set and prints precision, recall, F1 and ROC-AUC before saving `models/risk_model.joblib`.

## Frontend integration

Your CyberShield UI should call:

```text
POST /api/indicator/check
GET  /api/history
GET  /api/health
GET  /api/feeds
```

Do not hard-code threat records into the frontend. The frontend should render the API response, including evidence, provider errors, model status and risk reasons.
